## What the code is trying to do

The method `increasingTriplet` receives a vector of integers and has to answer the question:

> **“Does this array contain an increasing subsequence of length 3?”**

In other words, is there a triple of indices  
`i < j < k` such that `nums[i] < nums[j] < nums[k]`?

The algorithm uses two “place‑holders” (`first` and `second`) to keep track of the
smallest and second‑smallest values seen so far while scanning the array from
left to right.

---

## Step‑by‑step walk‑through

1. **Initialization**  
   ```cpp
   int first = INT_MAX, second = INT_MAX;
   ```
   * `first` will hold the smallest number seen up to the current position.
   * `second` will hold the smallest number that is *greater* than `first`
     (i.e., the second smallest in the partial subsequence).
   * Both start at the largest possible integer so that any real number in the
     array will replace them.

2. **Scan the array**  
   ```cpp
   for (auto a : nums) {
   ```
   We examine each element `a` one by one.

3. **Update `first`**  
   ```cpp
   if (a <= first) {
       first = a;
   }
   ```
   *If the current number is smaller than or equal to what we have stored in
   `first`, it becomes the new smallest number.*  
   Example: while scanning `[1, 3, 2, 5]`, after seeing `3` we set `first = 1`,
   then after seeing `2` we keep `first = 1` because `2 > 1`, but when we later
   see `0` we would update `first = 0`.

4. **Update `second` (if not a new `first`)**  
   ```cpp
   else if (a <= second) {
       second = a;
   }
   ```
   *Only if `a` is **greater** than `first` (because the first `if` failed) do we
   consider it for `second`.*  
   This means `second` will always be greater than or equal to `first`.  
   It represents the smallest value that can serve as the second element of a
   potential increasing triplet.

5. **Found a triplet**  
   ```cpp
   else {
       return true;   // we found a number > second > first
   }
   ```
   If the current number `a` is *greater than both* `first` and `second`,
   then we have discovered `first < second < a` in order, which is exactly an
   increasing triplet. The algorithm can immediately return `true`.

6. **Finish scanning**  
   ```cpp
   }
   return false;   // no triplet found after examining all elements
   }
   ```

If the loop ends without triggering the `else` clause, no increasing
subsequence of length 3 exists in the array, so the function returns `false`.

---

## Why this works

- **Greedy maintenance of minima**: By always keeping the smallest possible
  `first` and `second`, we maximize the chance of finding a larger third
  element later.  
- **Single pass**: We never need to remember the entire array; only two
  numbers are stored.  
- **Correctness proof sketch**:  
  * Suppose a triplet exists, say `x < y < z`.  
  * When we first encounter `x`, `first` will become `x`.  
  * When we later encounter `y`, `second` will become `y` (since `y > first`).  
  * Finally, when we see `z`, it will be greater than both `first` and `second`,
    triggering the `else` and returning `true`.  
  * Conversely, if the algorithm returns `true`, it has found numbers
    `first < second < a`, which is an increasing triplet.

## Complexity

| Metric | Value |
|--------|-------|
| Time   | **O(n)** – one scan over the array |
| Space  | **O(1)** – only two integer variables |

## Summary

The code implements a *greedy* linear‑time algorithm for detecting an
increasing subsequence of length three. It keeps track of the smallest
(`first`) and the second smallest (`second`) numbers seen so far, and as soon
as it finds a number larger than both, it knows an increasing triplet exists
and returns `true`. If the scan finishes without such a number, it returns
`false`.
